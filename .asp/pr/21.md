## 兩個 AC 之外的決定(都可一行拿掉)

1. **錯誤回應後的 lingering close**(`_Handler._drain_request_body`)。
   六道門全部在讀 body 之前判完——然後問題來了:被擋下的請求的 body 還在 socket
   裡沒讀,這時關連線,核心發的是 **RST** 而不是 FIN,而對方收到 RST 會把
   **連我們剛寫好的那個 413 回應一起丟掉**。所以錯誤回應**寫完之後**,才去把對方
   宣告的 `Content-Length` 讀掉(上限 1 MiB / 1 秒,超過就直接關,寧可讓對方吃
   RST)。要強調的是順序:**判斷**在讀 body 之前,**收尾**在回應之後,兩者不衝突
   (`test_lying_content_length_is_413_before_the_body_is_read` 守著前者:宣告
   1 GiB 的請求不會被讀,也不會讓伺服器掛著等)。
2. **V2 形式 fuzz 的縮小版**(`test_fuzzed_requests_never_5xx_and_never_traceback`)。
   決策 14 的 V2 寫「以 stdlib 固定 seed 對 HTTP 層打 10,000 筆」;本票 AC 沒列,
   而每筆一條 TCP 連線,10,000 筆在單元測試裡是 5 秒以上的固定成本。這裡放
   **2,000 筆**(約 1 秒)守一條不變式:任何畸形輸入都收斂成 4xx,沒有 `5xx`、
   沒有 traceback、伺服器還活著(最後一發正常請求必須回 200)。完整的 10,000 筆
   規模仍是人側 / 另一關的事,不在本票的 Done When 裡。

## 幾個實作選擇(與其理由)

### 「不能改綁定位址」在型別層面成立,不是靠文件

`make_server(port: int = 0)`——`127.0.0.1` 是模組常數 `LOOPBACK`,不是參數、
不從環境讀、沒有任何覆寫路徑。決策 4 要的保證因此不是「文件說不要改」,而是
**沒有那個參數可以傳**:要改得改那個常數,而那是一個 code review 看得見的 diff。
`test_bind_address_is_a_literal_not_a_setting` 連 `os.environ` / `os.getenv` 都掃掉
——「加個環境變數比較好部署」正是這道門最可能被繞開的方式。

### 兩張白名單,一條繫繩

決策 7 說 `/api/inspect` 的欄位「逐項等於 `cli._INSPECT_FIELDS` + `file_size`」,
但決策 13 不准 `webui` import `cli`(相依方向是 `cli → webui`)。兩條湊起來只有
一個解:表是**兩份**,然後用測試把它們綁起來。
`test_inspect_fields_match_the_cli_whitelist` 就是那條繫繩——它把 CLI 的標籤展開
(`kdf_id` → `kdf_id` + `kdf_name`)後與 `webui._INSPECT_FIELDS` 做 `==`,並且
斷言三張名字表(`scrypt` / `AES-256-GCM` / `scrypt-KEK`)內容相同。任一邊漂掉就
當場失敗,而不是在 UI 上默默少一欄。

表本身是「(鍵, 取值函式)」而不是 `dataclasses.asdict` / `vars()` / `FIELD_LAYOUT`
迴圈,理由同 `cli.py`:差別在**新增欄位時的預設行為**。迴圈式的寫法會讓 header
未來多出來的任何欄位(P1 的 ML-KEM 會加 `kem_pub` 之類的東西)**自動**被 JSON
吐出去;具名白名單的預設是「不吐」。

### 安全標頭注入在 `end_headers`,不是在每個回應點

放在自己的 `_respond` 裡只覆蓋「我們自己發的回應」;基底類別的 `send_error`
(畸形請求行、請求行過長)會繞過它,而那些回應一樣是這個伺服器說出口的話。
注入點收斂到 `end_headers` 一處之後,「漏一條路徑」的可能性是零——
`test_api_responses_carry_the_three_security_headers` 拿 10 種回應(含九種失敗)
逐一驗。

### `log_error` 整個收掉,不是改格式

基底類別用 `log_error` 記 `send_error` 的訊息,而那些訊息會**轉述請求行**
(`Bad request version ('…')`)。請求行是攻擊者寫的字串,不該由我們代為印到
使用者的終端上。狀態碼本身已經由 `log_request` 記過一次,沒有資訊損失。

## 三類必備測試(AGENTS.md 鐵律 4)在本票的落點

本票不含任何密碼學路徑(`inspect` 只讀明文 header、不碰 KDF 也不碰 AEAD),
故三類測試映到 HTTP 層:

- **round-trip**:`test_inspect_matches_the_cli_field_by_field`(golden 進去、
  12 個白名單欄位出來,**與 CLI 逐欄相等**)、`test_inspect_reads_only_the_header`
  (把 body 全砍掉照樣答得出來 → 沒有偷解 chunk 0)。
- **tamper**:`test_inspect_on_a_tampered_golden_is_422`(改 magic 一個 byte)、
  `test_inspect_on_broken_containers_is_422_with_the_cli_message`(空檔 / `QVLT` /
  `QVLT\x01` / 未知 version)、`test_inspect_on_a_non_container_is_422_with_the_cli_message`
  ——全部斷言**訊息逐字等於 CLI**(保證④:不區分密碼錯與竄改,UI 不自己加猜測)。
- **邊界**:六道門各自的拒絕碼(14 + 7 + 5 + 7 + 2 + 10 例)、65,536 / 65,537 bytes
  的上下界、宣告 1 GiB 的謊、空 body、非物件 JSON、缺檔 / 目錄 / 非普通檔、
  未預期例外 → 500、半截的 HTTP 請求、2,000 筆 fuzz。

## 對後續票的介面承諾
