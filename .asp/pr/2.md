### KAT 向量是字面值,不由實作輸出反推

沿用 #1 [M1] 的規矩:五組向量的 key/iv/pt/aad/ct/tag 全部是抄進測試檔的 hex 字面值。
反推的話,連「tag 放前面」都會「KAT 通過」——突變 F 正是這種。

## 做不到 / 打了折的,逐條說明

### 1. 票文的 `encrypt(plaintext, aad) -> (nonce, ct, tag)` **沒有照字面實作**

ROADMAP 那行(以及票文標題)寫的是 AEAD 層自己回一個 nonce。**這與 ADR-001 決策 5
直接衝突**,故採 AC 的 `seal`/`unseal` 簽章:

- 決策 5 把 nonce 定死成 STREAM 構造 `nonce_prefix(7B) ‖ uint32_BE(i) ‖ flag(1B)`,
  由 `container.nonce_for` 產生。AEAD 層若自產隨機 nonce,「`(prefix ‖ counter)`
  全域唯一、永不重用」這條**最關鍵的不變式**當場失效,末塊 flag 的防截斷([H2])
  也一起沒了。
- `docs/P0-acceptance-criteria.md` #2 的簽章是較晚、經**獨立密碼安全複審**補強的一份,
  且 AGENTS.md 明訂「worker 依 AC 施工」。ROADMAP 那行是 issue 的自動轉出來源,
  不是設計文件。
- 這個偏離是**可證偽**的:`test_seal_is_deterministic_and_never_invents_a_nonce`
  斷言同輸入同輸出、回傳長度恰為 `len(pt) + 16`(沒有多出 12B)、且 nonce 不出現在
  輸出裡。突變 G 證明它會殺掉「自產 nonce」的寫法。

回傳 `ct ‖ tag` 單一 bytes(而非 `(ct, tag)` 元組)同理:落盤格式就是 `ct ‖ tag`
(ADR 格式段「每塊落盤 = `ciphertext ‖ tag(16B)`」),多一層拆包只會多一個位元組界
歧義的機會。

### 2. 參數型別 / 長度錯丟 `ValueError`,不是 `QVaultError` 子類

AC 的「任一不符 → `QVaultDecryptError`」指的是**值**不符(錯金鑰、被改過的
ct/tag/nonce/aad)。長度不對是另一回事,沿用 #1 對 `nonce_for` 的同一條判準:

- `key` 與 `nonce` **永遠不來自 `.qvt`**——分別來自 `gen_dek`/`ScryptKEK` 與
  `nonce_for`。長度不對代表呼叫端寫錯,不是使用者拿到壞檔;報成 `QVaultDecryptError`
  會讓 CLI 把程式 bug 說成「密碼錯誤」,而真正的 bug 被靜音。
- **例外**:`sealed` 是唯一由檔案來的參數。它短於 tag(< 16B)是**竄改**,故走
  `QVaultDecryptError`,而且訊息與 tag 驗證失敗**逐字相同**——`test_truncated_sealed_raises`
  對 0..53 每一個截斷長度都測,`test_sealed_shorter_than_tag_is_a_decrypt_error`
  單獨釘死短於 tag 的那 16 種。
- 兩者的界線有測試守著:`test_value_errors_are_not_decrypt_errors`、
  `test_wrong_length_key_raises_value_error`、`test_wrong_length_nonce_raises_value_error`。

若 QA 要求統一成 `QVaultFormatError`,改動是 `_as_bytes()` 一行 + 測試的
`pytest.raises` 型別,無其他相依。

### 3. `aad=None` 不被接受(比 AC 嚴)

AC 沒說 `aad` 可否為 `None`。選擇**拒絕**:`cryptography` 的 `AESGCM` 把 `None` 當
空 AAD,於是一個「忘了傳 header」的呼叫端會**靜默**失去決策 6 的 header 綁定,而
round-trip 與竄改測試照樣全綠——正是複審講的「不必犯錯、只要做出合理選擇」那類洞。
空 AAD 必須明寫 `b""`(KAT TC13/14/15 就是空 AAD,照樣測)。

### 4. 常數與 `container` 的一致性用測試釘,不用 import

ADR 的相依圖裡 `container` 與 `aead` 是**兄弟**(`cli → vault → {container, aead, kek}`),
故 `aead.py` 不 import `container`。代價是 `NONCE_LEN = 12` 在兩處各有一份。
用 `test_constants_agree_with_container` 把兩份數字釘在一起,並順帶斷言
`WRAPPED_DEK_LEN == NONCE_LEN + KEY_LEN + TAG_LEN`(12+32+16 = 60,決策 11)——
#3 的 `wrap()` 輸出佈局因此在本層就有一條對帳。

`aead.NONCE_LEN` **刻意不**轉出到套件根:`container.NONCE_LEN` 同名同值,兩個都放到
`qvault_core.NONCE_LEN` 只會製造「這是誰的 12?」的疑問。要用請 `from qvault_core.aead
import NONCE_LEN` 或直接問 `nonce_for` 的輸出長度。

### 5. 沒做的(不是打折,是不在本票範圍)

- **nonce 重用的偵測**:本層無狀態,無從知道同一把 key 是否已用過某個 nonce。
  「不重用」是 #4 的 STREAM 迴圈與 #3 的 `wrap_nonce` 各自的責任,AC 也分別把
  證明放在那兩張票([L] 的 nonce 集合交集測試、[C2] 的前 12B 相異測試)。
- **金鑰歸零 / 記憶體擦除**:Python 的 `bytes` 不可變,無法可靠擦除;ADR 威脅模型
  明列「記憶體取證」為**不防**。不假裝做得到。
- **旁通道**:同上,「用受審庫緩解,**不宣稱**抗」。

## 對後續票的介面承諾

- **#3(`kek.py`)**:`ScryptKEK.wrap` 一律 `seal(kek, secrets.token_bytes(12), dek,
  b"QVLT-dek-v1")`,輸出即 `wrap_nonce ‖ seal(...)` 恰 60B;`unwrap` 走 `unseal`,
  失敗自然得到 `QVaultDecryptError`,且訊息與其他失敗路徑逐字相同——[M4]
  的「錯密碼 / 改 1 byte 兩路徑 `type` 與 `str` 完全相同」在本層就已成立,#3 只要
  不自己加訊息即可繼承。
- **#4(`vault.py`)**:每塊 `seal(dek, nonce_for(prefix, i, is_last), pt, header.aad())`;
  落盤就是 `seal` 的回傳值,不要再自己拆 ct/tag。解密側 `is_last` 由剩餘位元組數推導
  ([H2]),**不得**試誤——試誤在本層看起來只是「多呼叫一次 `unseal`」,但它把末塊
  flag 的防截斷保證整條抵銷掉。
- **金鑰不落地**:`gen_dek()` 的回傳值是金鑰,不得寫檔、進 log、進例外訊息(鐵律 5)。
