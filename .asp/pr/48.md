## W5 / W6 修的到底是哪半格

舊寫法把「換」與「記」綁在一個語句上:

```python
previous[sig] = signal.signal(sig, ignore)
```

`signal.signal()` 回來的那一刻處置**已經換掉了**,而 `previous[sig]` 的指派還沒
發生。信號落在那一刻(或任何事在那裡拋),`finally` 的還原迴圈看不到這個 `sig`:

- `_signals_deferred` 漏下的是 `ignore` → 之後**誰按 Ctrl-C 都沒反應**,而且看不出
  是誰改的(`cli.main` 是函式庫呼叫端也會用的進入點);
- `_signals_as_exit` 漏下的是 `_stop_on_signal` → 之後行程收到 `SIGTERM` / `SIGHUP`
  都會從一個早就結束的 `ui` 裡丟出 `_Stopped`,比沒裝更糟。

#42 L-5 修的是「整個迴圈漏在 `try` 外」(`finally` 根本不在路徑上),這一條修的是
迴圈**裡面**剩下的那半格。先記再換之後窗口的兩側反過來:記了但還沒換的話,
`finally` 把一個「本來就是它」的處置再裝一次,無害。

### 邊角:`except ValueError` 為什麼還要覆寫 `previous[sig]`

先記再換之後,`getsignal()` 已經把值寫進 `previous[sig]` 了,而接著的
`signal.signal()` 可能丟 `ValueError`(不是主執行緒)。那一格的意思是「**根本沒裝
上**」,所以 `previous[sig]` 必須被覆寫成 `_NOT_INSTALLED`——否則 `finally` 會在
非主執行緒上呼叫 `signal.signal()` 去「還原」一個我們從未裝上的處置,而那又是一個
`ValueError`,從 context manager 的 `finally` 裡冒出去。這是改順序時唯一新長出來的
邊角,兩個函式都寫了註解。
