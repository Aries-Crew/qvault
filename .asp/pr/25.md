**語料的邊界 = 本票主管層裁定 ①,逐條落在程式碼裡**(`test_webui_fuzz.py` 的模組
docstring 寫了同一段理由):

1. 所有 JSON 的 `path` 一律在 `tmp_path` 內。AC 字面寫「`path` 指向…golden」,這裡
   用的是 golden 的**複本**(`tmp_path/golden_copy.qvt`),不是 `tests/vectors/` 裡
   那一份——裁定明令不得命中它。
2. `/api/encrypt` 的 `path` 池子**不含任何存在的普通檔**,所以 `_input_file` 一定
   在 `_passphrase` 之前就拒掉 → 一次 scrypt 都不派生、一個檔都不寫。
3. `/api/decrypt` 的 `out_dir` 池子**不含任何真目錄**(`_api_decrypt` 的順序是
   輸入檔 → `out_dir` → 密碼),同樣在 KDF 之前就拒掉。

這三條前提本身由 `::test_the_corpus_never_offers_encrypt_an_existing_path` 這條
**不打伺服器**的測試守著:前提破掉時的徵狀(偶發多出一個 `.qvt`、偶發變慢)是最
難追的那一種,所以讓語料自己先被驗一次。

另外,語料給「對的那個值」高權重(`Host` 85%、token 70%、合格 `Content-Type`
55%、POST 50%)。理由寫在檔裡:等機率的 fuzz 會讓一萬筆的九成九卡在第一道門上,
後面五道門與三個端點一個都沒走到——綠得很好看但什麼都沒驗。量尺是
`EXPECTED_AT_LEAST`:這一輪必須**真的**回過 200 / 400 / 401 / 403 / 404 / 405 /
413 / 415 / 422 各至少一次(實測分佈 `{200: 295, 400: 587, 401: 314, 403: 2097,
404: 484, 405: 5102, 413: 63, 415: 1044, 422: 14}`)。`409` 不在下界裡——它只在
encrypt 真的寫得下去時才出現,而裁定 ① 正是把那條路堵掉的。

## 三處判讀(票文沒有正面寫到、我這樣做的理由)

### 判讀 ① getpass 的夾具:在新檔**複寫**一份,不搬進 `conftest.py`

AC 寫「getpass 比照 `tests/test_cli.py` 的 fixture 餵答案」,而共同範圍條款禁止
修改既有測試,AGENTS.md 又禁止測試檔 import 另一個測試檔(gate 的 ruff 會判
F401 + F811)。triage 留言點出這一點並建議「搬進 `conftest.py` 或在新檔複寫一份,
AC 直接指定哪一種」——票文最後沒有指定,所以我選**複寫**:

`tests/conftest.py` 是一個**既有**檔案,而且它的 `server` 夾具餵著既有的
整批 Web UI 測試。在裡面動刀的風險(即使只是新增一個夾具)全落在裁判凍結的那一側;複寫的
代價是 `tests/test_e2e_ui_cli.py` 裡多 14 行一個最小的假 `getpass`,風險是零。
`tests/test_cli.py` 一個 byte 都沒碰。

### 判讀 ② import 邊清單:AC 的 15 條 + 對帳補上的 6 條,分開記帳

AC 的清單(15 條)**沒有列到** `__init__.py` 的邊,而 AC 同時寫著「實際以現況
為準」。施工當時的現況多出 6 條,兩類都**不是本票加的**:

* `__init__ → {aead, container, errors, kek, vault}` —— `__init__.py` 是公開 API
  的 re-export 面(`from .aead import DEK_LEN, …`),它 import 五個下層模組是這個
  套件的門面設計,不是一條新的相依方向;
* `cli → __init__` —— `cli.py` 的 `from . import __version__`(`--version` 的
  來源)。方向仍是「上層 → 門面」,`__init__` 不 import `cli`,故不成環。

處理方式:`AC_EDGES`(15 條,逐字照抄票文)與 `PACKAGE_FACADE_EDGES`(6 條,對帳
補上)是**兩個常數**,`ALLOWED_EDGES` 是它們的聯集,而
`::test_the_ac_edge_list_is_recorded_verbatim` 斷言「AC 那份一條不少、聯集減掉
AC 恰為門面那 6 條、門面那 6 條每一條都以 `__init__` 為一端」。這樣下一個人一眼
看得出哪些是裁定過的、哪些是對帳出來的(triage 建議 ③ 要的就是這個)。

順帶一提:這張清單在施工時**真的抓到我自己抄漏了一條**(`vault → errors`),
測試先紅才改對——它的「新邊要改測試才會過」是驗過的,不是宣稱的。

triage 建議 ③ 還提到「與 #36 的落點對帳」:#36 要改 `qvault ui` 的開瀏覽器機制
(跳轉檔)。本輪**沒有**辦法對帳——worker 無 GitHub 存取,#36 的內容不在簡報裡。
若 #36 的實作落在 `webui.py` 並新增內部邊,`::test_no_internal_import_edge_outside_the_hardcoded_list`

### 判讀 ③ `HEAD` 的回應沒有 body,所以那一筆驗狀態碼而不驗 `error`

AC 寫「非 2xx 的 body 皆可 `json.loads` 且含 `error`」,而語料的 method 集合含
`HEAD`。依 RFC 9110 §9.3.2,`HEAD` 的回應**不得**帶 body,`_respond` 也照辦
(`if self.command != "HEAD": self.wfile.write(body)`),而 `http.client` 對 HEAD
一律把回應長度當 0 —— 所以那些筆拿到的 `body` 必然是 `b""`,`json.loads` 必然
失敗。這不是伺服器的瑕疵,是 HTTP 的規定。

處理方式:HEAD 那一支驗「狀態碼 ∈ 封閉集合」+「`body == b""`」+「`Content-Length`
標頭仍宣告出來」;其餘方法的非 2xx 驗「`json.loads` 得開 + 是 dict + 含 `error` +
`error` 是字串 + `Content-Type` 是 `application/json; charset=utf-8`」。
AC 的允許集合沒有放寬,一萬筆**每一筆**的狀態碼都照驗。

## 那一處產品碼改動:`webui.py` 的方法 catch-all(裁定 ②)

主管層裁定 ② 允許「`webui.py` 補一個 catch-all,把沒有 `do_<METHOD>` 的方法統一
回 405,不讓標準庫回 501」。實作是 `_Handler.__getattr__` 的 5 行:

```python
def __getattr__(self, name: str) -> object:
    if name.startswith("do_") and len(name) > 3:
        return self._dispatch
    raise AttributeError(name)
```

**一件要先說清楚的事實**:裁定的 blocker 敘述(「fuzz 的 method 集合含
PUT / DELETE / HEAD / OPTIONS，而 CPython 對沒有 `do_<METHOD>` 的方法回 501」)
對本票的語料**其實不成立**——`_Handler` 從 #21 起就有
`do_GET` / `do_HEAD` / `do_POST` / `do_PUT` / `do_PATCH` / `do_DELETE` / `do_OPTIONS`
七個具名賦值,而 AC 的 method 集合(GET / POST / PUT / DELETE / HEAD / OPTIONS)
是它的子集。所以**就算不改 `webui.py`,fuzz 也不會碰到 501**。

那為什麼還是改了:裁定授權的那件事本身是對的,而且改完之後「不回 501」從「我們
恰好列了七個動詞」變成**型別層面成立**。`TRACE` / `PROPFIND` / `BREW` 這些動詞
打進來時,原本會拿到標準庫的 `501` + 一份 **HTML** 錯誤頁 —— 狀態碼不在決策 14
的封閉集合裡,body 不是本層唯一的錯誤形式,還順手把「這是個
`BaseHTTPRequestHandler`」告訴了打進來的人。現在它們拿到跟 `PUT /` 一模一樣的
那一句 `405 {"error": "method not allowed"}`。

邊界守得很緊,三件事值得記下來:

1. **沒有放行任何方法。** catch-all 只決定「進不進 `_dispatch`」;受不受理仍由
   `_handle` 判(靜態路由只收 GET / HEAD,`/api/*` 只收 POST)。所以那七個具名
   賦值不是白名單,只是具名的常見動詞;上面那串保留著不刪,它們比
   `__getattr__` 好讀。
2. **只接 `do_` 開頭的名字**,其餘照常 `AttributeError`。`_drain_request_body` 的
   `getattr(self, "headers", None)` 與 `_route` 的 `getattr(self, "path", "")` 必須
   維持「真的沒有就是沒有」的語意 —— 那兩個預設值處理的正是「請求行還沒解析成功」
   的情況,一個吃掉所有名字的 `__getattr__` 會把它們變成「永遠拿得到東西」。
   `::test_the_catch_all_only_answers_do_names` 直接斷言 `do_` / `headers` /
   `path` / `_body_consumed` / `nope` 五個名字照樣拋 `AttributeError`。
3. **AC 的允許集合沒有放寬**,501 沒有被納入。`ALLOWED_STATUS` 逐字就是票文那
   十個碼。

補的測試:`::test_an_unknown_method_is_405_json_not_501_html`(5 個動詞 × 3 條
路徑 = 15 格,逐格驗 405 + `{"error": "method not allowed"}` + JSON
`Content-Type` + 三個安全標頭)、`::test_the_catch_all_only_answers_do_names`、
`::test_an_unknown_method_does_not_print_a_traceback`(順帶驗 access log 仍是
`<method> <path> <status>` 一行)。
