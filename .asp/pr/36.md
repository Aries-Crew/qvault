# fix(cli): #36 開瀏覽器改走只有啟動者讀得到的跳轉檔——帶 token 的網址不再進任何程序的 argv

Closes #36

`qvault ui` 原本把 `http://127.0.0.1:<port>/#<token>` 直接交給 `webbrowser.open`,
而瀏覽器若原本沒開,標準庫走的是 `xdg-open <url>` / `firefox <url>`:那條**帶
token 的網址**於是在那支程式的整個生命期裡躺在 `/proc/<pid>/cmdline`,預設沒有
`hidepid` 的 Linux 上同機其他使用者 `ps aux` 就拿得到,接著能以啟動者的身分讀寫
本機檔案(ADR-002 決策 2 的路徑模式)。

這一趟照**使用者 2026-11-10 的裁定(選 A:改機制)**比照 Jupyter:自動開瀏覽器時
改開一個**只有啟動者讀得到的本機跳轉檔**,交給瀏覽器命令列的只有一條 `file://`
網址。**終端印出的那一行網址一個字都沒變**(終端私有的假設照舊),故 #24 那幾條
「印出來的第一行」「信號 5 秒內 exit 0」的子程序測試一條都沒改。

合併前複審(`CHANGES_REQUESTED`,2026-11-14)的兩條擋合併與三條順手修都處置完了
(逐條見下方「合併前複審的處置」);其中 B1 的第三格要求 fail-closed,所以產品碼
多了一道門:0700 / 0600 是**量過**的,不是信 `mkdtemp` 與 `os.open` 的要求——
實測 `umask 0177` 下那個目錄其實是 `0600`,連啟動者自己都進不去。

實測(真行程,`BROWSER` 指到一支記下 `"$@"` 的腳本):

```
$ qvault ui --port 0
http://127.0.0.1:45839/#j5owCWKhbLJWpFSzMEsaF9QbMYEJk3ruGHmzS3GN3lY   ← 終端照舊
瀏覽器收到的 argv:  file:///tmp/qvault-ui-bymxyjwy/open.html           ← 一個 token 字元都沒有
700 /tmp/qvault-ui-bymxyjwy        600 /tmp/qvault-ui-bymxyjwy/open.html
SIGINT / SIGTERM / SIGHUP → rc=0,且 TMPDIR 底下回到空的;埠被占 → rc=1 且什麼都沒寫
```

### 為什麼住在 `cli.py` 而不是 `webui.py`

「怎麼把網址交給瀏覽器」這一步發生在 `webbrowser.open` 的呼叫點,而呼叫點在
`cli.py`;`webui.py` 是那個**伺服器**,它連「有沒有人要開瀏覽器」都不知道。
另外 ADR-002 決策 13 的相依邊被 #24 凍成測試
(`test_the_cli_takes_exactly_two_names_from_webui`:`cli` 只能從 `webui` 取
`LOOPBACK` 與 `make_server`),把跳轉頁放進 `webui` 再 import 過來會當場踩紅它,
而那條邊的粗細本身就是決策 13 要守的東西。

### 四個刻意的選擇

1. **`O_CREAT|O_EXCL` + mode `0o600`,不是先建檔再 `chmod`**:後者在那兩步之間
   檔案的權限是 `0o666 & ~umask`,而 umask 是使用者環境裡的變數。這個宣稱的證人
   是 `test_the_file_is_created_with_o_excl_at_0600_and_never_chmodded`(spy 記下
   `os.open` 的 flags 與 mode、禁止任何 `chmod`)+ `test_the_cli_has_no_chmod_anywhere`
   (AST 掃整個檔案);`test_a_wide_open_umask_still_produces_0600_and_0700` 守的是
   另一件事(umask 加不了位元)。
2. **`location.replace(...)` 而不是 `<meta http-equiv="refresh">`**:`replace` 不留
   瀏覽器歷史(按上一頁不會回到那個檔案),`meta refresh` 會。
3. **網址以 `json.dumps` 算成 JS 字串字面值**,不是手寫 `"{url}"`:今天網址全由
   我們自己組(`LOOPBACK` 是常數、埠是 int、token 是 `token_urlsafe` 的 base64url),
   沒有可注入的字元;用 `json.dumps` 是為了讓這句話明天還成立。
   `test_the_redirect_url_is_a_js_string_literal_not_a_hand_rolled_quote` 以 AST 守著。
4. **權限是量過的,不是信的**(複審 B1 的第三格):`mkdtemp` 的 0700 與 `os.open`
   的 0600 都只是**要求**,umask 遮得到——實測 `umask 0177` 下 `mkdtemp` 給的是
   0600(少了 `x`,連啟動者自己都進不去那個目錄)。那一形不是「安全性少一點」,
   是**整個機制默默失效**:瀏覽器打不開那一頁,使用者只看到空白視窗,而 token
   已經落地。故建立之後各量一次(目錄 `os.stat`、檔案 `os.fstat` 於已開好的 fd),
   不符就一行乾淨錯誤 + exit 1、不留檔、不開瀏覽器(終端那條網址仍在、
   `--no-browser` 仍走得通),**不**事後 `chmod` 補回去。

## 已知限制

- **攔不住或我們沒處理的致死信號會留下殘留**:`SIGKILL`(`kill -9`)攔不住,而
  `SIGQUIT`(Ctrl-\)、`SIGUSR1/2`、行程崩潰走的是預設處置——`_STOP_SIGNALS` 只
  處理 `SIGTERM` / `SIGHUP`。這一形已寫進 ADR-002「不防」,並說明殘留只有啟動者
  讀得到(檔案 0600、目錄 0700,前綴 `qvault-ui-` 讓使用者找得到它)——對同機其他
  使用者而言它不是新的洩漏面,代價是使用者自己得去刪。**不把那幾個信號全加進
  `_STOP_SIGNALS` 是刻意的**:那會改掉 `ui` 對它們的語意(例如 `SIGQUIT` 的 core
  dump),超出本票範圍,而 #40 另有一票在動這塊信號處理。
  (這一條的措辭是複審 S1 校回來的:第 1 世的 help / README / ADR 寫「除了
  `kill -9`,任何停法都會刪檔」,那句話把 `SIGQUIT` 這一類漏掉了。)
- **umask 把那兩個權限遮掉時,`qvault ui` 整個失敗**(exit 1、不留檔、不開瀏覽器),
  不是「改用別的方式開瀏覽器」:那是複審 B1 要的 fail-closed。替代設計是「不開
  瀏覽器但繼續服務 + 一句警告」,它對使用者更寬容,但會讓「停下來」這件事變成
  一句容易被滑過去的 stderr——取捨記在這裡,改回來只要動 `_require_private_mode`
  一個函式。終端那條網址在這條路徑上**照舊印出來**,`--no-browser` 也照舊走得通。
- **Ctrl-C 來得極快時瀏覽器可能讀不到那個檔案**:`webbrowser.open` 回來只代表
  那支程式被 spawn 了,不代表它已經把檔案讀完。退出序列先等開瀏覽器那條執行緒
  (`UI_BROWSER_SECONDS` = 0.5 秒,有界)再刪,已經把窗口縮到最小,但這不是一個
  保證。後路是終端上那一行網址(它沒變)。
- **snap / flatpak 封裝的瀏覽器可能打不開 `/tmp` 裡的 `file://`**:那種封裝給瀏覽器
  一個私有的 `/tmp` namespace(Jupyter 的同一套做法踩過這個)。這一形在 worker
  裡驗不了(**worker 不跑瀏覽器**,ADR-002 決策 14),屬合併前人側驗收項;若遇到,
  使用者的後路同樣是終端那條網址或 `--no-browser`。本票沒有改 `webbrowser` 的
  選擇邏輯,也沒有加任何選項去繞它(那會超出票文範圍)。
- **權限位元的量測與斷言都只在 POSIX 上**:Windows 的 `mkdtemp` 目錄回報 `0o777`、
  `os.open` 的 mode 只認唯讀位元,私有性靠的是 per-user 的 `%TEMP%` 與目錄 ACL,
  不是 0700 / 0600。故 `_MODES_ARE_MEANINGFUL`(`os.name == "posix"`)在那一側把
  整道門關掉——不關的話每一次 `qvault ui` 都會被自己判成失敗
  (`test_the_mode_check_is_posix_only_so_windows_can_still_open_a_browser` 守著
  這一點)。`mkdtemp` 在兩邊都是「只有建立者能進去」的那個語意,但**本票只在
  POSIX 上以 `stat` 實測過**;Windows 的那一側沒有任何自動化證人。
- **「token 不寫進任何其他檔案」的驗證範圍**是暫存根目錄(恰一個目錄、恰一個
  檔案),不是整個檔案系統;終端那一行是決策 12 要的,不在這條的範圍內。
- **in-flight drain 期間跳轉檔還活著**:退出序列先等在途的 `/api/*`(最多 3 秒)
  再刪檔,所以收到停止信號後那個檔案最多多活 3.5 秒。它整段期間的權限沒變
  (只有啟動者讀得到),而伺服器那一刻也還在服務,故這不是一個新的暴露面。
- **gitleaks 未在本容器內實跑**(無該執行檔),由 gate / CI 的 `secrets` job 把關。
  本趟沒有新增任何金鑰或 token 形狀的字面值;測試裡用的是 `"A" * 43` 這種假 token。
