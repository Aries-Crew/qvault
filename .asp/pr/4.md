## 做不到 / 打了折 / 比 AC 嚴的,逐條說明

### 1. chunk 0 **補零到恰好 4096**,而不是「總長 ≤ 4096」的變長塊(唯一一處與 AC 字面不同)

AC 與 ADR 決策 13 寫「總長 ≤ 4096」,讀起來像變長。本實作補零到**定長 4096**
(落盤 4112 B)。兩個理由,**缺一不可**:

1. **不補滿就解不開。** [H2] 要求 `is_last` 由剩餘位元組數推導、**禁止**試誤法,
   於是解密端必須在解密**之前**就知道每一塊的位元組界。資料塊有 `chunk_size` 可推,
   chunk 0 的長度卻是 `2 + name_len + 8`——而 `name_len` 正在那塊還沒解開的密文裡。
   header 沒有任何欄位記 chunk 0 的長度(加一個就等於明文洩檔名長度,牴觸決策 9),
   兩端唯一能對齊的常數就是 ADR 自己寫的那個 4096。變長 + 禁止試誤 = 無解。
2. **不補滿就洩檔名長度。** 決策 9 把檔名加密進 `.qvt` 是為了不洩檔名;若 chunk 0
   隨檔名伸縮,`ls -l` 就能從 `.qvt` 的位元組數反推 `name_len`(其餘各段長度都是
   已知常數)。補到定長,這條旁通道消失。

於是「≤ 4096」成為 `2 + name_len + 8 ≤ 4096` 的**上界檢查**(`_pack_chunk0` 與
`_parse_chunk0` 兩端都檢),而尾端填充**必須全為零**——留一段「解密端不看」的位元組,
等於在一個宣稱「格式固定」的容器裡開一條隱藏通道(`test_chunk0_plaintext_layout`
與 `test_malformed_chunk0_raises_format_error` 各守一半)。

**這是格式決定,不是實作細節**,故 QA 第二輪的 minor 一併處理掉了:
`docs/adr/ADR-001-crypto-core-architecture.md` 的**決策 13 與 `.qvt` 格式段已補記**
「補零至恰好 4096B、填充必須全為零」與上面兩條理由(AGENTS.md:格式的唯一事實源
是 ADR-001,勿在他處另複製格式——原本只寫在 `vault.py` 的 docstring 裡就是第二本帳,
而依 ADR 字面實作變長塊的解碼器會與本實作互不相容)。

**`version` 維持 1**:v1 在 #4 之前沒有任何實作寫過 chunk 0(本票是第一份),
不存在需要相容的舊檔,故這是**釐清**而非不變式④ 說的格式變更。ADR 裡也照這樣註明。
`test_adr_is_the_single_source_of_the_chunk0_layout` 掃描 ADR 文字並與
`CHUNK0_PLAINTEXT_LEN`/`CHUNK0_SEALED_LEN` 對帳,讓「改了實作沒改 ADR」當場失敗。

### 2. `encrypt_file` 也套同一套檔名淨化(比 AC 嚴)

AC 只要求解密端淨化。本實作在加密端先跑一次同樣的 `_sanitize_name`:否則
`encrypt_file` 會樂意產出一個**自己永遠解不開**的 `.qvt`。代價是少數在 Linux
合法、在 Windows 不合法的名字(`trailing.`、`CON`、`x:y`、非 UTF-8 檔名)**不能加密**,
當場 `QVaultFormatError`(`test_encrypt_refuses_a_name_it_could_not_restore`)。

判準是「**哪一種失敗比較好**」:當場說「這個檔名不能加密」可以改名重試;
產出一個能加密不能還原的保險庫,發現時通常已經把原檔刪了。

QA 第二輪判讀為「理由成立、方向正確,但屬**票外的行為擴張**且會打到 #5 的 CLI
使用者,建議由人裁示,至少讓錯誤訊息可操作」。故本輪**只改訊息、不改行為**:
現在丟的是 `input file name cannot be restored on every platform (<具體原因>);
rename the file and encrypt again`(仍不回填檔名)。**行為留給 human reviewer 裁示**
——要放寬,拿掉 `encrypt_file` 開頭那一個 `_sanitize_name(...)` 呼叫即可,
解密端與其他 AC 都不受影響;#5 的 CLI 只要把這句訊息原樣印出來就是可操作的指引。

### 3. 兩個函式都有 `force=False`,預設拒絕覆寫

AC 只替 decrypt 寫了「目標已存在預設拒絕(`--force` 才覆寫)」。`encrypt_file`
同樣預設拒絕:靜默蓋掉一個既有的 `.qvt`(可能是**別的**檔案的保險庫)是不可逆的
資料損失,而 AGENTS.md 繼承的四鐵則明列破壞性動作禁止。#5 的 CLI 若要
「encrypt 直接覆寫」,傳 `force=True` 即可——見下方介面承諾。

### 4. 串流結構的錯誤訊息與 AEAD 失敗**不同字**(型別相同)

- 錯密碼、竄改、AAD 不符 → `QVaultDecryptError("AEAD authentication failed")`,
  **逐字**沿用 `aead` 那一句,本層一個字都不加(`test_wrong_passphrase_and_tamper_are_indistinguishable`
  同時比 `type` 與 `str`)。
- 截斷/重排/長度對不上 → `QVaultDecryptError("chunk stream is truncated, reordered or incomplete")`。

理由:第二類的判斷**只用公開資訊**——`.qvt` 在磁碟上的位元組數,以及**已經通過
AEAD 驗證之後**才拿到的 `orig_size`。攻擊者 `ls -l` 就知道長度對不對,訊息裡沒有
他還不知道的事,故不構成 oracle;而所有真的「解不開」的路徑仍不可區分。
若 QA 要求全部收斂成同一句,改 `_STREAM_BROKEN` 一個常數即可。

### 5. `out_dir` 不存在 → `NotADirectoryError`,不是 `QVaultError`

沿用 #2/#3 的判準:**看這個值從哪裡來**。`out_dir` 是**呼叫端**傳的,不是 `.qvt`
裡的欄位,傳錯是程式/使用者的操作錯誤,不是「檔案格式壞掉」。同理,輸入檔不存在
是 `FileNotFoundError`、目標已存在是 `FileExistsError`——都留在 `OSError` 家族,
讓 #5 的 CLI 能分開報「用法錯」與「檔案壞/密碼錯」。

### 6. `_open_private` 的 `os.chmod(0o600)` 是**備援**,拿掉不會有測試死

如實列出:突變 M(拿掉那行 chmod)**沒殺死任何測試**,因為 `tempfile.mkstemp`
建立時就是 `0o600`,權限性質仍然成立(`test_temp_file_is_owner_only_while_it_exists`
照樣綠)。留著它是因為 [M9] 逐字要求「暫存檔**建立時**皆 `0o600`」,寫出來讀者
不必去查 `mkstemp` 的文件;它包在 `try/except OSError` 裡,Windows 上不報錯。

### 7. `encrypt_file` 多一個 `chunk_size` 關鍵字參數

AC 的簽章是 `encrypt_file(inp, out, passphrase)`,本實作在其後加了
`*, chunk_size=65536, force=False`(**都是關鍵字**,位置參數與 AC 逐字相同)。
`chunk_size` 的用途:測試要造五塊檔只需 16 KB 而不是 320 KB,#5 的 `inspect`
也能對照。合法值完全交給 `QVaultHeader` 把關(`[4096, 1048576]` 且為 2 的冪),
`vault` **不自己另立一套界限**(`test_encrypt_rejects_an_illegal_chunk_size`)。

### 8. 加密端也做了原子寫(AC 沒要求)

`.qvt` 同樣先寫暫存檔再 `os.replace()`。半個 `.qvt` 被誤認成完整保險庫、而原檔
已經刪掉,是本工具最糟的失敗模式;成本只有幾行。`test_failed_encryption_leaves_no_partial_qvt`
守著。

### 9. 沒做的(不是打折,是不在本票範圍)

- **CLI**(`encrypt`/`decrypt`/`inspect`、`getpass`、exit code)是 #5。本票不新增
  `cli.py`,`pyproject.toml` 既有的 `[project.scripts]` 指向的仍是 #5 要建的檔。
- **目錄項的 fsync**:暫存檔本身有 `os.fsync`,但沒有 fsync 父目錄。那是**斷電後
  的耐久性**問題,不是原子性問題(`os.replace` 的原子性由檔案系統保證),ADR 未要求。
- **金鑰歸零**:Python 的 `bytes` 不可變,ADR 威脅模型明列「記憶體取證」為不防。
- **`.qvt` 的長度旁通道**:密文長度仍然洩漏原檔大小(±一塊)。ADR 未把它列為目標,
  補起來要加填充塊,屬格式變更(version +1)。
- **並行安全**:同一個 `out_dir` 同時解兩個同名檔會有 TOCTOU(兩邊都通過
  「已存在」檢查,後者 `os.replace` 贏)。暫存檔是 `O_EXCL` 的獨立名字,故不會互相
  覆寫到一半;要真正互斥需要檔案鎖,不在 P0 範圍(QA 同意)。修掉 blocker 之後,
  這條的最壞後果已從「悄悄在 `out_dir` 留下一個含完整明文的 `.qvault-*.part`」
  降為「乾淨地報錯、零殘留」。
