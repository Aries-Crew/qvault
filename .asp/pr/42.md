## 本世:CI 紅燈(第 1/2 世改派)修的是什麼

`asp-ci` 的 `tests` job 在 head `816a568` 上紅一條:

```
FAILED tests/test_project_contract.py::test_the_readme_section_points_at_every_test_file
  AssertionError: README 的測試分層沒提到這些檔:['test_webui_log_premise.py']
1 failed, 1305 passed in 46.31s
```

**為什麼 worker 容器沒看到**:那條測試與它守的 README 小節是**代發前最後一次 base
同步**(`816a568`,併入 `origin/develop @ baa0120`)才從 #25 帶進工作卷的——它比
dev 與 QA 兩世的全套測試都晚。那條契約測試要求 `tests/test_*.py` 的**每一個**檔都
在 README 的分層表裡被點名(新增一個測試檔就得補一行),而本票新增的
`tests/test_webui_log_premise.py` 當時還沒有那一行。

**修法**:把它補進「HTTP layer」那一列(它確實是 HTTP 層:用 `server` 夾具打真
socket,外加一條 AST 掃描),並把本世新增的 `tests/test_cli_signals_restore.py` 補進
「unit」那一列。產品碼與既有測試都沒有因為這條紅燈被動到。


### F6 的「或」為什麼選 (a)

票文給了兩條路:(a) docstring 寫明前提 + 加一條「`_route` 不得 `unquote`」守衛

擇一(票上留言 ① 建議「開票端擇一並釘死」,票文與裁定都沒釘)。選 (a),兩個理由:

1. **裁定的字面已經預期 (a) 的形狀**:「F6 的守衛測試為新增檔案,不受凍結限制」
   ——(b) 這條路上沒有「守衛測試」這個東西,只有跳脫語意的改動。
2. (b) 動的是**產品的跳脫語意**,而本票是「不擋合併的 low 集中清理」。在沒有人裁
   的情況下擴到產品行為,代價是 `_CONTROL_CHAR_TABLE` 的覆蓋範圍與
   `test_the_control_char_table_covers_c0_c1_and_del`(既有、凍結中)的關係要重新
   談,而那條測試不在本票的許可清單裡。

**(b) 真的多蓋一層,這點不否認**(本機 Python 3.12.14 核對:U+0085 是 `Cc`、
U+2028 是 `Zl`、U+202E 是 `Cf`),所以 `_escaped` 的 docstring 把它寫成一條交代:
真的哪天需要百分號解碼,改表(改依 `unicodedata.category`)要與那次改動**同一個
commit**。要走 (b) 的話是另一張票的事,這裡不預先替它做決定。
