### medium ①:`wrapped_dek` 的長度歧義

`memoryview` 的 `len()` 是**元素數**不是**位元組數**。QA 的重現我先確認為真:

```
>>> h = QVaultHeader(..., wrapped_dek=memoryview(array("I", range(15))))   # len()=15, bytes()=60B
>>> len(h.serialize()), int.from_bytes(h.serialize()[38:40], "big"), h.body_offset
(100, 15, 55)          # 吐 100 byte,卻宣告 15,而 body_offset 回 55
```

這正是 [H5] 要防的 AAD 位元組界歧義——#2 拿 `body_offset` 去切 AAD 就會切錯 45 byte,
**而兩邊都不會自曝**。修法採 QA 建議的第二個(較徹底的)版本:`__post_init__` 以
`object.__setattr__` 把 `magic`/`salt`/`nonce_prefix`/`wrapped_dek` 正規化成 `bytes`,
「長度」從此只有一個定義。`serialize()` 改用同一份已驗證的 bytes;`body_offset` 對壞
`wrapped_dek` 改為 raise `QVaultFormatError`——**回一個錯的位元組界比 raise 危險得多**。

非位元組型別(`None`/`str`)刻意不在 `__post_init__` 處理,留給 `_validate()` 報
`QVaultFormatError`,免得建構期丟出型別不對的例外。

新增回歸測試:`test_bytes_fields_are_normalised_to_bytes`(含 QA 那個
`array("I", range(15))` 夾具)、`test_bytes_like_inputs_compare_equal`、
`test_body_offset_raises_on_malformed_wrapped_dek`。

### medium ②:讓 [H1] 的 Scrypt 斷言真的載重

QA 說得對:`monkeypatch.setattr(scrypt_mod, "Scrypt", ...)` 打的是**模組屬性**,
若實作用 `from ...scrypt import Scrypt` 在模組層綁名,呼叫走的是已綁定的原始參考,
patch 打不到。「Scrypt 從未被呼叫」有三種逃法,現在三種都堵:

1. `scrypt_mod.Scrypt(...)` 屬性存取 → monkeypatch 的假類(建構即記錄並炸);
2. 模組層 `from ... import Scrypt` 綁名 → 新增
   `test_container_namespace_holds_nothing_from_cryptography`:掃 `vars(container)`,
   任何 `__module__` 落在 `cryptography` 的物件(或 module 物件本身)都算違規;
3. 函式內延遲 import → 新增 `builtins.__import__` 守衛,只罩住那一次 `deserialize`
   呼叫的窗口。守衛期間**不用** `pytest.raises`(它組失敗訊息時自己會 import,
   會誤觸守衛),改成自己接例外再斷言型別。

**突變實測**(把一個真的過早 `Scrypt(n=2**kdf_log2n)` 注入到界限檢查之前,三種綁名
風格各一輪):

| 注入風格 | 全場 failed | AC 指名的 `test_bounds_checked_before_scrypt` |
|---|---|---|
| A 模組層 `import ... as _s` + 屬性存取 | 8 | **failed** ✅ |
| B 模組層 `from ... import Scrypt` 綁名 | 6 | pass(打不到是本來就預期的)——由**命名空間掃描**擋下 ✅ |

`chunk_size=0xFFFFFFFF` 兩個 case,兩者都跑在三重守衛底下。

順帶接受 QA 的提醒:**「呼叫端拿 header 參數去餵 Scrypt」的順序,要在 #2/#3 的整合層

## 做不到 / 打了折的,逐條說明

### 1. 「每欄位各改一次都 raise」——`salt` / `nonce_prefix` / `wrapped_dek` 三欄在本層做不到

這三欄是**不透明位元組**:任何 16B / 7B / 60B 的值在純 struct 層都是合法 header,
沒有任何判準能說某個 salt「壞掉了」。硬要讓它 raise 只能捏造規則(例如「salt 不得
全零」),那是假的檢查,而且會誤殺合法檔。

改為在本層釘死兩件**真的能釘死**的事:

- **長度不符必 raise** —— `test_each_field_has_a_mutation_that_raises` 對這三欄用截斷;
  serialize 側 `test_bounds_enforced_on_serialize_too` 用 15/17B salt、6/8B prefix、
  59/61B dek。
- **沒有任何一個 byte 被靜默忽略** —— `test_every_byte_flip_raises_or_changes_header`
  把 100 個 offset 逐一翻轉,要求**要嘛 raise、要嘛解出不同的 header**(實測 17 個
  raise、83 個解出不同 header,兩條分支都真的走到)。這比原句更強:它證明每一個
  byte 都進了 `serialize()` 的輸出,也就是進了 AAD。

改一 byte 的**偵測**因此落在 AAD 上。**交接條件(QA 的 L2,勿在 #2 掉包)**:#2/#4
的 tamper 測試必須包含「`salt` / `nonce_prefix` / `wrapped_dek` 各改一 byte → 解密必
raise `QVaultDecryptError`」三條,這張票的偏離才算真的補完。

### 2. [H3] 空檔正規佈局:本層只能做到一半

「body 只有 chunk 0」是**檔案層**的寫入行為,`container.py` 不寫 body,無法端到端驗。
本張票交付的是它的判準,且這一趟把它從「測試手傳 True」升級成程式推導:

- `body_chunk_count(0, cs) == 1`(含 chunk 0,不補零長度資料塊;`(4096, 4096) == 2`
  證明整除時也不多補一塊)
- `is_last_chunk(0, 1) is True` → `nonce_for(prefix, 0, ...)[11] == 0x01`

**#4 必須用這兩個函式決定塊數與末塊 flag**;完整的「空檔 round-trip 後 body 恰一塊」
留在 #4 的 AC。

### 3. `nonce_for` 的 `index >= 2**32` 丟 `ValueError`,不是 `QVaultError` 子類

AC 只寫「raise」未指定型別。選 `ValueError` 的理由:`.qvt` 裡**根本沒有 index 這個
欄位**(它是解密迴圈的計數器),越界代表呼叫端寫錯,不是使用者拿到一個壞檔;混進
`QVaultFormatError` 會讓 CLI 把程式 bug 報成「檔案損毀」。`prefix` 長度不符同理。
QA 這一輪未對此提出異議;若仍要統一到 `QVaultFormatError`,改動是 `container.py`
兩行 + 測試的 `pytest.raises` 型別,無其他相依。

(對照:`is_last_chunk()` / `body_chunk_count()` 用的是 `QVaultFormatError`——它們的
輸入 `orig_size` / `chunk_size` **確實**來自檔案內容,與 `index` 不同。)

### 4. 超出 AC 字面、但我加了的東西(逐項理由)

- `QVaultHeader.aad()` / `.body_offset` —— [H5] 說「這個位元組界一旦歧義,兩個實作會
  互不相容,而各自的測試都會通過」。給它一個名字,#2/#4 就不必再猜。
- `is_last_chunk()` —— 見 low L1。
- **白名單 `__repr__`**(`<QVaultHeader version=1 … chunk_size=65536>`)—— 預設
  dataclass repr 會把 `wrapped_dek` 吐進 `logging.exception` 與 pytest 的 locals
  展開,正是決策 20 / [M7] 要擋的事。
- `salt`/`nonce_prefix`/`wrapped_dek` **沒有預設值** —— 有預設值就是常數 salt,
  決策 10 明令禁止;連手滑的機會都不留(`test_header_has_no_default_secrets`)。
- `FIELD_LAYOUT` —— 線格式的機讀轉錄,讓邊界測試逐欄掃而不必在測試裡再抄一份 offset。
- `test_no_import_random_in_package` —— 決策 20 的 `import random` 禁令,以 AST 斷言。
  嚴格說屬 #2 的 [L],但它守的是我這張票就已存在的 `qvault_core/`,先放進來零成本。

沒有新增任何相依(`container.py` 只 import stdlib;`cryptography` 僅出現在 [H1] 那組
測試的 monkeypatch 目標,且以 `pytest.importorskip` 保護)。
