## 幾個實作選擇(與其理由)

### `inspect` 是白名單,而且是**具名**白名單

`_INSPECT_FIELDS` 是一張 `(標籤, 取值 lambda)` 的表,不是 `vars(header)` /
`dataclasses.asdict` / `FIELD_LAYOUT` 迴圈。差別在**新增欄位時的預設行為**:迴圈式的
寫法會讓 header 未來多出來的任何欄位**自動**被印出來(P1 的 ML-KEM 會加 `kem_pub` 之類的
東西),而黑名單「印全部,除了那三個」只要漏更新一次就洩一欄。具名白名單的預設是
「不印」,要多印一欄得有人動手改表,程式碼審查看得見。突變 J(改成 `vars(header)` 傾印)
會殺掉 11 個測試。

### 錯誤訊息一個字都不加

`QVaultDecryptError` 的訊息(`AEAD authentication failed`)直接轉述,**不**加「密碼可能
錯誤」——ADR 保證③ 花力氣讓「錯密碼」與「被竄改」不可區分,在最外層補一句猜測等於把
那個 oracle 裝回去。`test_wrong_passphrase_message_does_not_guess` 拿「錯密碼」與「改一個
byte」兩條路徑跑出來的訊息**逐字比對相等**,並禁掉 passphrase/wrong/tamper 等字眼。

### 「不吐 traceback」包含**我們自己的 bug**

`main()` 最後有一個 `except Exception`,只印 `internal error (<型別名>)`。traceback 的
frame 裡躺著密碼與 DEK(鐵律 5),而它出現的場合(使用者的終端、螢幕截圖、工單)正是
最不該有這些東西的地方。`test_unexpected_exception_still_prints_no_traceback` 讓
`encrypt_file` 丟一個**訊息裡含密碼**的 `RuntimeError`,斷言輸出只有型別名。
代價是我們自己 debug 時看不到 traceback——但那時可以直接呼叫函式庫,而使用者不行。

### 密碼的三道關卡都在進 KDF 之前

空字串、兩次不一致、無法 UTF-8 編碼(孤兒代理對,例如 Windows argv 經 `surrogateescape`
進來的位元組)。第三道特別繞了一下:`UnicodeEncodeError` 的訊息會**把出錯的那個字元印
出來**,而那是密碼的一部分,故本層自己 `try/except` 後丟一句不含該字元的話
(`test_passphrase_with_unencodable_characters_fails_cleanly` 兩項都斷言)。

### exit code

`0` 成功、`1` 操作失敗(所有乾淨錯誤)、`2` argparse 自己的用法錯誤、`130` Ctrl-C。
`main()` **回傳** exit code 而不呼叫 `sys.exit`——console script 的 wrapper 做的就是
`sys.exit(main())`,測試因此可以直接斷言回傳值;`python -m qvault_core.cli` 的那兩條
subprocess 測試則證明它在真行程裡確實傳得到 shell(接不上的話所有 `&&` 都會誤判成功)。

## 沒做的(不是打折,是不在本票範圍)

- **`--chunk-size` 之類的調參旗標**:`encrypt_file` 收 `chunk_size`,但 AC 沒要求開放,
  而開放它等於讓使用者能產生一個對自己不利的 header;預設 64 KiB 走 `vault` 的預設。
- **shell 補全、彩色輸出、進度條**:純 UX,AC 未列,且進度條會把「檔案多大」寫進終端。
- **`BrokenPipeError` 的優雅收尾**(`qvault inspect big.qvt | head`):它是 `OSError`,
  已走乾淨錯誤出口回非零,只是直譯器結束時可能另外印一行 `Exception ignored`。
  要完全消掉得動 `sys.stdout` 的收尾,不在 AC。
- **從 stdin 讀密碼給腳本用**(`--passphrase-file` / `QVAULT_PASSPHRASE`):AC 明令密碼
  只走 `getpass`,而這類旗標正是它要防的那條路;真要自動化請直接用函式庫。
